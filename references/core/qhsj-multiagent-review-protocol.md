# QHSJ 多智能体并行分析、冲突仲裁与回归验收协议

## 1. 目标与边界

本协议给支持多智能体、子代理或多角色审查的宿主提供可执行的分工合同。多智能体不是为了同时输出多份互相矛盾的成品，而是把高复杂度任务拆成互相独立的检查面，再由统一总控合并证据、解决冲突并运行回归测试。宿主没有真实子代理能力时，总控可以按相同角色顺序逐轮执行，但不得谎称已启动独立智能体。

## 2. 角色编组

### R0 任务总控 / 首席导演（Orchestrator）

接收原始用户请求，建立任务卡、约束清单、工作范围和验收表；决定哪些评审并行、哪些需要等待前置产物；维护唯一的当前版本；处理智能体之间的冲突；在交付前逐项回看用户原话。

### R1 需求与 Canon 审核员

只负责逐句拆分用户目标、交付物、数量、格式、平台、硬约束、否定项、保留项和未决变量。不得擅自修改故事事实或视觉资产；输出要求映射表和遗漏风险。

### R2 路由/架构审计员

检查能力 ID、触发词、依赖闭包、工作流入口、工作流到资源、资源到章节、别名到规范文件以及脚本调用关系。每条缺陷必须附文件路径、行号或 JSON 节点、复现请求和预期/实际差异。

### R3 领域专家组

根据任务选择小说/编剧、分镜摄影、模型适配、提示词、美术、表演、音频、VFX、API/宿主适配等专业角色。只审查分配范围，引用具体资料并输出可合并的修订建议，不得对自己未负责的项目 Canon 作未经授权改动。

### R4 资产与空间连续性审计员

专门核验角色身份、场景结构、道具持有、人物间距离、身体和头部朝向、视线目标、摄影机位置、轴线、动作路径、起止状态和物理反馈。缺少坐标/实际尺寸时，标注“需补资料”或使用明确相对关系，不编造测量精度。

### R5 红队 / 矛盾与边界检查员

尝试用边界输入、否定句、复合白话、同义替换、缺失字段、错误路径、重复资源、冲突约束和异常输入触发错误。检查是否误路由、漏路由、过路由、静默删项、无限循环、无效依赖、空输出和错误地把计划写成执行成功。

### R6 回归测试与构建审计员

运行静态检查、路由用例、单元测试、YAML/JSON/Schema 校验、引用检查、资产约束检查和打包重现测试。用新的边界案例复现每个修复，不得只修改断言让失败变成通过。

## 3. 并行分工规则

在共享的任务输入只读副本上工作；每个角色有明确职责和输出格式。独立审查可以并行：需求核验、资源分类、脚本静态检查、模型知识时效审查和空间规则审查。存在数据依赖的任务必须串行：先建立资产目录，再生成角色/场景资产；先锁定资产，再做分镜资产；先修路由代码，再运行依赖此代码的评估；先更新注册表，再生成路由图和 Manifest。

任何代理不得直接覆盖同一份主文件。各代理输出补丁或结构化问题报告，总控按条目合并。重复报告按缺陷 ID 合并，保留全部证据来源。观点冲突不按多数票决定，而按以下顺序处理：安全/政策边界 > 用户明确硬约束 > 可追溯源文件事实/Canon > 已验证技术事实 > 空间与物理可行性 > 交付协议 > 风格建议。

## 4. 标准缺陷记录

每条发现至少包含：`issue_id`、严重级别（P0/P1/P2/P3）、类别、证据路径、行号/JSON 路径、输入复现、当前结果、期望结果、影响范围、根因、修复方案、受影响依赖、回归测试 ID、修复状态和残余风险。没有证据的印象式结论只可列为待调查猜测，不得直接用于删除内容。

- P0：包无法解析、主入口不可用、核心数据丢失、错误执行高风险操作。
- P1：明确任务漏路由、用户硬约束被覆盖、资产身份/空间因果严重错误、资源路径断裂、关键流程依赖顺序反了。
- P2：部分工作流过触发、变量缺省、检查不充分、格式不一致、可复现的次级缺陷。
- P3：文案、排版、命名或可维护性问题，不影响核心执行但建议修正。

## 5. 合并与修复闭环

1. 锁定基线版本和原始文件清单。
2. 需求审核员把用户请求拆成有唯一 ID 的验收条款。
3. 总控按依赖关系生成任务图并分派审查角色。
4. 并行审查返回结构化发现，所有结论附证据。
5. 总控去重同根因问题，保留独立的功能差异；不能把“标题相似”当作“内容相同”。
6. 实施最小充分修复，保留来源事实和未受影响核心段落；删除内容前必须证明其为完全重复且通过别名/规范源机制保留了原文。
7. 更新资源注册、触发词、能力标签、工作流连接、章节索引、Schema 和 Manifest。
8. 运行静态审计和所有回归测试，再追加针对修复点的反例测试。
9. 若有失败，按根因回退对应节点继续修复；不得通过降低覆盖断言、吞异常或将失败改成警告来制造通过。
10. 逐项对照原始用户要求，报告已完成、未完成、受工具限制和无法验证的项目。

## 6. 路由协议

复杂或全面整改类请求必须触发 `skill_architecture_audit`、`quality_assurance` 和 `general_orchestration`，并加载本协议。若任务涉及图像/视频生成，还需按实际范围加载对应创作能力；单纯审查路由时，不得因为知识库中包含创作模块就输出无关小说、分镜或提示词。

## 7. 诚实执行边界

子代理规划不等于子代理已真正运行。每个工具调用必须有实际返回才能标记执行成功。脚本测试通过只说明本地测试集覆盖范围内未发现失败，不等于数学意义上保证零 Bug。对第三方模型、在线 API、平台审核规则或用户环境没有实时证据时必须标记待验证，并给出可复现实测步骤。
