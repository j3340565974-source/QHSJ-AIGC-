# 空间一致性与空间推理引擎

## 0. 核心

“空间事实优先”。先建立固定场景模型，再生成镜头。

## 1. 双坐标体系

### 世界坐标

- X：场景固定横向
- Y：高度
- Z：场景固定深度

### 屏幕坐标

- screen-left / screen-right：只表示当前镜头画面中的左右
- near / mid / far：当前镜头的前中后景

世界坐标不随摄影机改变；屏幕左右由机位推导出来。

## 2. 场景锚点

每个场景至少 5 个稳定参照物：

`门 / 窗 / 柱 / 桌 / 灯 / 楼梯 / 墙角 / 路牌 / 大树 / 建筑边缘`

锚点必须在多个镜头中可识别。

## 3. 环境护照

```yaml
scene_id: S01
fixed_anchors:
  - A: "入口门"
  - B: "售货机"
  - C: "窗"
lighting:
  key: "左后方暖光"
  fill: "弱冷环境光"
  shadow_direction: "右前方"
characters:
  A: {start: "靠近门", facing: "朝向B"}
  B: {start: "售货机旁", facing: "朝向A"}
objects:
  phone: {owner: A, hand: "自身右手", state: "屏幕朝上"}
axis: "A-B"
continuity_notes: []
```

## 4. 行动闭环

每次移动写：

`起点 → 路径 → 终点 → 朝向变化 → 速度 → 接触反馈`

例如：

`站在桌左侧 → 沿桌边向窗移动 → 停在窗前 → 身体转向窗、脸保持朝室内 → 慢走 → 鞋底持续接触地面`

## 5. 180° 轴线

对话或明确空间对立建立 A-B 轴。

反打不能凭“习惯”写；必须由相机位置推导。越轴时需要：

- 中性轴线镜头
- 环绕穿越轴线的显式运动
- 空镜/遮挡作为重置
- 或用户明确要求故意跳轴

## 6. 视线

对视：A 向右、B 向左只是常见画面规则，不是绝对物理定律；必须结合实际机位和脸部朝向检查。

记录三项：

`身体朝向 / 头部朝向 / 眼睛视线`

## 7. 反打几何

A 正面镜头 → 记录 A 背后的真实背景。

B 正面反打 → 记录 B 背后的真实背景。

不能把“B 正面”误写成“B 身后还是 A 的背景”。

## 8. 物体状态账本

每个有戏剧功能的物体记录：

`位置 / 朝向 / 所属人物 / 手持手 / 开关状态 / 完整度 / 是否受力 / 上一镜终态`

## 9. 相机状态

记录：

`位置 / 高度 / 朝向 / 镜头焦段 / 目标点 / 运动方向 / 起幅 / 终幅`

## 10. 帧链

`shot N end_state == shot N+1 start_state`

允许变化只有两类：

- 在镜头间明确发生
- 由时间跨越解释

否则判定为连续性错误。

## 11. 防穿模检查

检查：

- 手与物体是否有接触面
- 脚与地面是否有支撑
- 身体是否穿过墙、门、桌
- 衣服、长发、武器是否穿过人体
- 物体遮挡关系是否稳定
- 阴影是否与主体位置一致

## 12. 空间 Bug 根因

- 未锁定锚点
- 只写屏幕左右，不写世界关系
- 角色身份与位置同时变动
- 镜头之间缺少终帧状态
- 多人没有唯一 ID
- 反打依赖语言而不依赖几何
- 参考图和文字描述互相矛盾
- 过度复杂动作导致模型跳帧

## 13. 最终空间门禁

没有场景锚点、没有角色位置、没有轴线（如涉及对话/对立）、没有前后镜状态传递时，不输出“保证连续”的提示词。
